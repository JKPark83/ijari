2. Supabase 프로젝트 생성

  1. 조직/프로젝트 생성 — 리전은 반드시 Northeast Asia (Seoul). 사용자와 데이터가 전부 한국이다.
  2. DB 비밀번호는 생성 직후 비밀번호 관리자에 보관. (분실 시 리셋 가능하지만 연결 문자열이 바뀐다.)
  3. SQL Editor에서 PostGIS 활성화: 
    create extension if not exists postgis;
select postgis_full_version();   -- 완료 판정 1번
  4. 키 3종을 구분해서 보관한다:
    키성격두는 곳
    anon key공개 키. RLS가 지켜준다는 전제로 앱에 넣는다Phase 3에서 iOS 코드 상수로
    service_role keyRLS를 무시하는 관리자 키. 유출 = DB 전체 노출로컬 pipeline/.env만. 절대 커밋 금지
    DB 연결 문자열ETL의 COPY 적재용pipeline/.env의 SUPABASE_DB_URL
  5. 쓰지 않는 기능은 꺼둔다: Authentication 프로바이더 전부 비활성(익명 앱), Realtime 비활성.

DB 연결 문자열은 "Session pooler" (포트 5432)를 쓴다. 프로젝트 대시보드 Connect 화면에서 Direct connection이 아니라 Session pooler 문자열을 복사할 것. Direct 주소(db.*.supabase.co)는 IPv6 전용이라 IPv4만 되는 집 회선에서는 붙지 않는 함정이 있다. COPY·트랜잭션 모두 session 모드에서 정상 동작한다.

무료 티어는 1주일 동안 요청이 없으면 프로젝트가 일시정지(pause)된다. 개발 공백기가 생기면 대시보드에서 수동 재개해야 한다. 앱이 갑자기 안 붙으면 십중팔구 이것부터 확인.

4. 분기 CSV 확보

공공데이터포털 "소상공인시장진흥공단_상가(상권)정보" 파일데이터 페이지의 "주기성 과거 데이터" 섹션에서 받는다. 기획서 검증 결과대로 2023 Q1(2023-03-31 기준) 이전 파일은 오염돼 있으므로 받지 않는다.

  1. 지금 필요한 것: 2023Q1 서울 + 최신 분기 서울 두 개 (Phase 1 스파이크용). 나머지 분기는 Phase 2에서, 타 시도는 Phase 5에서 추가로 받는다.
  2. 전국 zip을 받아 서울 CSV만 꺼내는 형태일 수 있다 — 어느 쪽이든 data/raw/{분기}/에 원본 그대로 넣는다.
  3. 폴더 규약: data/raw/2023Q1/소상공인시장진흥공단_상가(상권)정보_서울_202303.csv 처럼 분기 폴더 아래 원본 파일명 유지.
  4. download.py는 이 시점엔 "URL 매핑 테이블 + 없으면 수동 다운로드 안내"만 있으면 된다. 포털의 파일별 고유 URL을 확보할 때마다 매핑에 추가한다.
  5. 받은 파일은 지우지 않는다 — 포털 아카이브를 신뢰하지 않는 것이 기획의 결론이므로, data/raw/가 우리의 원본 보관소다. (git 제외, 필요하면 외장/클라우드 백업.)

행 수·인코딩 확인 (완료 판정 3번):

file data/raw/2023Q1/*.csv          # 인코딩 확인: UTF-8인지 CP949인지
uv run python - <<'EOF'
import duckdb
for q in ("2023Q1",):  # 최신 분기도 같이
    n = duckdb.sql(f"select count(*) from read_csv_auto('data/raw/{q}/*.csv')").fetchone()[0]
    print(q, f"{n:,}행")
EOF

인코딩이 CP949로 나오면 read_csv_auto(..., encoding='cp949')가 아니라(DuckDB 미지원) iconv -f cp949 -t utf-8로 변환본을 만들어 쓴다. 변환본은 data/utf8/{분기}/에 두고 원본은 건드리지 않는다.
