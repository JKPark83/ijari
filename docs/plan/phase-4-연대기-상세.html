Phase 4 — 자리 연대기 상세 화면

이 앱의 존재 이유가 완성되는 phase. "이 자리, 주인이 4번 바뀌었습니다"가 화면에 뜬다

선행: Phase 3 · 예상 2~3일 · 다음: Phase 5 전국 확장

✅ 완료 판정 — 실기기에서 확인

  1. 자리 마커를 탭하면 바텀시트가 올라오고, 헤드라인·타임라인·동네 비교가 모두 보인다.
  2. Phase 1 게이트 20곳 중 아무 자리나 찾아 들어가면 내 기억과 부합하는 연대기가 보인다.
  3. 층 미상(confidence low) 자리, 다점포 자리, 공실 후보, 교체 0회 자리 네 가지 케이스 모두 문구가 어색하지 않다.
  4. 현재 위치 버튼을 누르면 권한 요청 → 내 주변으로 지도가 이동한다 (거부해도 앱은 정상).
  5. 화면 어딘가에 기준 분기("2026년 2분기 데이터 기준")가 항상 보인다.

이 판정을 통과하면 MVP 기능이 완성된 것이다. 이후는 데이터 확장(5)과 출시(6)다.

1. 화면 구조 — 바텀시트

// MapScreen에 붙이는 시트. medium이 기본, 끌어올리면 large
.sheet(item: $selectedPlaceKey) { key in
    PlaceDetailSheet(placeKey: key)
        .presentationDetents([.medium, .large])
        .presentationBackgroundInteraction(.enabled(upThrough: .medium))  // 지도 계속 조작 가능
}

데이터는 place_detail RPC 한 번으로 받는다 (자리 + 연대기 + 동 통계가 한 JSON). 시트가 올라온 뒤 로딩 스피너 → 내용 교체. 실패 시 시트 안에 재시도 버튼.

2. 헤드라인 문구 — 케이스가 전부다

이 화면의 품질은 코드가 아니라 문구 분기가 결정한다. String Catalog에 다 넣고, 케이스별로:

케이스 (판정 조건)헤드라인보조 문구
단일 점포 자리, 교체 N≥1"이 자리, 주인이 N번 바뀌었습니다""평균 M개월마다 새 가게가 들어왔어요"
교체 0회 + 데이터 시작부터 영업"한 가게가 3년 넘게 지키고 있는 자리""2023년 1분기부터 계속 영업 중"
다점포 자리 (stores_current ≥ 2 또는 이력상 동시 2곳 이상)"이 층 점포 N곳 · 교체 M번""층 단위 정보라 점포별 구분은 정확하지 않을 수 있어요"
공실 후보 (is_occupied=false)"지금은 비어 있는 것으로 보이는 자리""마지막 영업 기록: {end_quarter}"
confidence=low (층 미상)(위 문구 그대로)추가 배지: "층 정보 없음 — 건물 단위 추정"

단정적인 표현은 피한다: 공실은 "비어 있는 것으로 보이는", 층 미상은 "추정". 데이터 원천(자영업자 신고 기반 수집)의 한계 때문에 확언하면 반드시 틀린 사례가 나오고, 그게 앱 신뢰를 깎는다. 기획서의 "폐업 단정 금지" 원칙을 UI로 구현한 것이다.

3. 타임라인

  • history 배열을 seq 역순(최신이 위)으로 세로 타임라인에 그린다. 현재 영업 중(end_quarter == null)인 항목은 강조색 점 + "영업 중".
  • 표기는 업종명 + 기간뿐이다. 상호명은 스키마에 아예 없으므로 실수로도 노출될 수 없다 (Phase 2에서 강제됨).
  • 기간 표기: 2023.1분기 ~ 2024.2분기 (1년 3개월). tenure_quarters × 3개월로 환산하되 "약"을 붙이지 않는다 — 분기 해상도라는 건 하단 데이터 기준 문구가 설명한다.
  • 다점포 자리는 타임라인에 기간 겹침이 자연스럽게 존재한다 — 겹침을 버그로 취급하지 말고 그대로 그린다 (세로 나열이므로 겹쳐 보일 일도 없다).

업종 이모지 매핑

대분류 코드 → 이모지 딕셔너리 하나. 매핑 표는 지어내지 말고 실제 데이터의 select distinct 상권업종대분류코드, 상권업종대분류명 결과(10개 내외)를 보고 작성한다. 매핑에 없는 코드는 기본값 🏪.

4. 동네 비교 한 줄

place_detail의 dong 객체로 계산한다. 자리 교체 수 vs dong.turnover_avg:

  • 2배 이상: "이 동네 평균({avg}번)보다 눈에 띄게 잦은 자리예요"
  • 평균 근처(0.5~2배): "이 동네 평균({avg}번)과 비슷한 수준이에요"
  • 절반 이하 또는 0회: "이 동네 평균({avg}번)보다 오래 버티는 자리예요"

배수 표현은 avg가 0.5 미만이면 생략(0에 가까운 수로 나누면 "10배" 같은 과장이 나온다).

5. 현재 위치

  • 지도 우하단 위치 버튼 → CLLocationManager.requestWhenInUseAuthorization() → 승인 시 내 위치로 카메라 이동 (줌 레벨 places).
  • 거부 시: 버튼 비활성 + 탭하면 설정 앱 이동 안내. 위치는 편의 기능일 뿐 앱의 전제가 아니다 — 권한 없이 모든 기능이 동작해야 한다.
  • avg_tenure 표시 규칙: 종료된 점유가 하나도 없는 자리는 avg_tenure_months가 null → "—" 또는 문구 생략. 0으로 표시하지 않는다.

6. 데이터 기준 표시 (항상)

앱 시작 시 app_meta를 한 번 읽어 (latest_quarter, coverage) 메모리에 둔다. 지도 하단 또는 시트 하단에 상시 노출: "2026년 2분기 데이터 기준 · 서울 · 소상공인시장진흥공단 상가(상권)정보". 분기 갱신이 늦어져도 사용자가 낡은 데이터를 최신으로 오해하지 않게 하는 최소 장치다.
